# D60 — API reports and the name `DocumentObject`

- Status: Accepted — by the project owner on 2026-11-03, after PR-37 was merged
  (PR #38)
- Date: 2026-11-03
- Supersedes: —
- Closes: the open items of D42.11 and D43.8 that name the public `NodeData`
  type
- Related: D11, D37, D39, D45, D46,
  [roadmap of phase four](../roadmap/phase-4.md) PR-37 and questions 2 and 3

## Context

The first host compiles against the `.d.ts` of the packages. Nothing in the
repository showed when a pull request changed that surface: a renamed field of
an exported interface, a removed export, or a widened parameter landed as a
side effect of a diff about something else, and only a reader of every
changed `.d.ts` could see it. Phase four makes the surface a reviewed contract
(phase four, "The public surface is reviewed"), and the host should compile
against names that will not change for naming reasons.

`@kadrion/editor-sdk` had two names for one type. `NodeData`
(`commands.ts`) typed the node of `AddNode`, and also the animation,
keyframe, clip, scene, transition, effect, word, style, input, binding,
condition, and repeat that other commands carry. `DocumentObject`
(`document.ts`) is the same `Readonly<Record<string, unknown>>`, used for
every object of the document that the registry reads. D42.11 and D43.8 left a
neutral name open.

The owner accepted the recommendations of the phase four plan on 2026-11-03:
a small script over the TypeScript compiler API rather than API Extractor
(question 3), and a rename without an alias (question 2), because no host has
installed a release yet (no `v0.N.0` tag exists).

## Decision

**60.1 One report per package.** Each package commits `api-report.txt` at its
root. It is generated from the package's built `.d.ts` and holds, for each
entry of the `exports` map in map order, every exported name in code point
order with the declarations it resolves to, printed by the TypeScript printer
without comments. An interface, a class, an enum, a type alias, or the type of
a constant is printed whole, so a changed member changes the report. An export
made by `export type` is marked `(type only)`, because a class exported that
way has no value. An untyped entry, such as a file of the runtime build, is
listed by its path. A type the package does not export appears only by name
inside the signatures that use it.

**60.2 Generated by a script on the compiler.** `tests/api/api-report.ts`
reads the entries with the TypeScript compiler API of the pinned `typescript`
development dependency (D11); one program reads every entry, so a type
re-exported from another package resolves to the declaration that package
built. `node --run api:update` builds and writes every report. No new
dependency and no per-package configuration is added.

**60.3 The report is a gate.** `tests/api/api-report.test.ts`, part of
`check`, fails when a committed report and the built surface differ, naming
the first differing line, and when a package has no report. A pull request
that changes an exported type, function, or constant changes the report of
that package in the same diff, and its description says whether the change is
additive or breaking.

**60.4 A breaking change needs a minor version.** A change that removes or
renames an export, removes or renames a member, narrows what a function
accepts, or widens what it returns is breaking. Under D45 every package
carries one version `0.N.0`; a release that contains a breaking change of a
report raises `N`. An additive change may ship in the same `N`. Reports are not
shipped: the tarballs keep `package.json` and `dist` only (45.3).

**60.5 `DocumentObject`.** `NodeData` is renamed to `DocumentObject`, the name
`document.ts` already used for the same shape, and the one definition stays in
`document.ts`; `@kadrion/editor-sdk` exports it as a type. No alias for the old
name is kept. The rename changes no emitted JavaScript, no document, and no
tool of the catalogue: the snapshot of D46 stays byte for byte.

## Alternatives considered

- **API Extractor** — a dependency and a configuration per package for
  features the repository does not use (doc models, release tags, trimmed
  declaration rollups). The repository already pins the compiler it needs.
- **Reporting names only** — cheaper, but a changed member of an exported
  interface, the most likely breaking change for a host, would not show.
- **Following every referenced type into the report** — complete, but a
  report of `@kadrion/editor-sdk` would repeat much of the schema; the type of
  an export is printed where it is declared, and the schema's own report
  carries the schema's types.
- **Keeping `NodeData` as a deprecated alias for one release** — no host code
  uses it yet, and an alias is a second name to document and remove.
- **A new name such as `JsonObject`** — `DocumentObject` already names the
  type inside the package, so one name for one type needs no new word.

## Consequences

- Every package gains `api-report.txt`; `tests/api` holds the generator, the
  writer, and the gate. The root gains `node --run api:update`.
- `@kadrion/editor-sdk` exports `DocumentObject` and no longer `NodeData`;
  `commands.ts` imports the type from `document.ts`. `@kadrion/ai-sdk` used
  neither name, so it is unchanged.
- The runtime build, the Player's dist tree, golden frames, parity, and Q14
  are unchanged: no package of the runtime build changes, and no pinned file
  does.
- A pull request that changes a `.d.ts` without running `api:update` fails
  `check`.
- D42.11 and D43.8 record that the name is decided here.

## Verification

- `tests/api/api-report.test.ts`: every package has a report; the reports are
  generated the same way twice; each committed report equals the built one;
  every entry of each `exports` map is named; the report of
  `@kadrion/editor-sdk` exports `DocumentObject` and no report names
  `NodeData`; the members of an exported interface are printed.
- `packages/ai-sdk/test/catalogue.snap` is unchanged by the rename.
